# Manual QA Internship — Project Case Study

## Project Overview

This case study summarizes my hands-on experience in manual quality assurance testing of a web-based SaaS application during my QA internship.

The application consisted of multiple interconnected modules designed to support user management, dashboard operations, data management, workflow systems, content-related activities, and account management.

My primary responsibility was to independently evaluate application functionality, validate user workflows, identify defects, and report issues to improve the overall quality, usability, and reliability of the application.

**Project Type:** Web Application  
**Role:** Manual QA Intern  
**Testing Approach:** Independent Manual Testing  
**Project Stage:** Development and Testing

---

## Roles and Responsibilities

### 1. Functional Testing
- Validated application features against their intended behavior.
- Tested buttons, forms, navigation elements, and interactive components.
- Verified functionality across different application modules.
- Identified unexpected behavior and functional inconsistencies.
- Evaluated positive and negative user scenarios.

### 2. UI Testing
- Evaluated visual consistency across application pages.
- Verified element alignment, positioning, spacing, and visibility.
- Checked buttons, popups, navigation menus, and interface components.
- Identified layout inconsistencies and usability-related issues.

### 3. Responsive Testing
- Tested application behavior across different viewport sizes.
- Evaluated desktop and mobile layouts.
- Identified overlapping, clipped, or improperly positioned elements.
- Verified navigation and interaction usability on smaller screens.

### 4. End-to-End User Flow Testing
- Independently evaluated complete user journeys.
- Verified navigation between interconnected modules.
- Tested workflows involving authentication, dashboard operations, data management, and content-related activities.
- Identified interruptions and inconsistencies within user workflows.

### 5. Exploratory Testing
- Explored application features without relying entirely on predefined test scenarios.
- Identified defects through systematic application exploration.
- Investigated unexpected behavior and edge cases.
- Tested areas where formal requirement documentation was unavailable.

### 6. Defect Identification and Reporting
- Identified functional, UI, usability, and responsive defects.
- Reproduced issues to confirm their occurrence.
- Documented defect descriptions, reproduction steps, expected results, and actual results.
- Assigned defect priorities based on impact.
- Reported identified issues through the internal defect reporting process.
- Attached supporting evidence to defect reports where applicable.

### 7. Retesting and Regression Testing
- Retested reported defects after fixes were implemented.
- Verified whether the observed issues were resolved.
- Performed regression-oriented checks on related functionalities.
- Evaluated whether application changes introduced new issues.

## Testing Methodology

Testing was performed independently using a practical manual QA approach.

The general workflow followed was:

1. Explore the application and understand its modules.
2. Identify important functionalities and user journeys.
3. Determine relevant test scenarios.
4. Perform functional, UI, responsive, and exploratory testing.
5. Reproduce and investigate identified defects.
6. Document and report defects with clear details.
7. Retest reported issues after fixes.
8. Perform regression-oriented checks on related functionalities.

The testing process required independent analysis because formal requirement documentation was not consistently available.
